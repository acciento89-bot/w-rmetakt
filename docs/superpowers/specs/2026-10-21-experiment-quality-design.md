## Domain and precise rules
- New schema1 QualityReview holds experimentId, four ISO dates (beforeStart/beforeEnd/afterStart/afterEnd) and exclusions[{phase,date,reason}]. Inclusive windows must each contain3..31 dates, have equal length, and beforeEnd < afterStart. Strict real Gregorian YYYY-MM-DD; defaults use existing experiment startedAt UTC day: preceding durationDays dates, then startedAt through durationDays−1. Existing7/14-day choices remain unchanged.
- Review dates are explicitly UTC calendar dates. Timestamps with explicit timezone are normalized to UTC day; do not reinterpret ISO dates using device locale/DST. UI labels state UTC. Raw measuredAt remains unchanged. Valid measurements outside phase/date windows remain in history and outside-selection count.
- Each selected phase/date has0,1 or multiple raw records. Missing dates are listed; multiple records on one day are flagged, never guessed/summed/averaged into an invented daily record. Every original ID/value stays in database.
- Core numeric validity: all recorded numeric fields finite; electricity/heat/starts/runtime/hotWater nonnegative, starts integer. Temperatures may be negative; existing optional flow/return sentinel0 remains allowed. A selected included invalid row or duplicate day blocks a numeric comparison rather than silently dropping it. At least3 distinct included days per phase are required. Missing coverage otherwise remains visible as a review warning.
- Flag unusual weather-normalized electricity only with at least3 valid unique-date records in that phase and positive median: value <0.5× or >2× phase median. It is a transparent heuristic for review, not a fault diagnosis or automatic exclusion. Flags are computed from all selected records and remain visible when excluded.
- Explicit phase/day exclusion affects all raw records on that phase/date in this worksheet only, requires trimmed nonblank reason≤500characters, one decision per phase/date and a date within its window. No silent exclusions. All decisions remain accessible while editing windows so users can reinstate/remove a now-outside decision. Invalid visible dates/reasons disable Save and stale numeric preview.
- All selected versus reviewed cohorts use the existing analyzeMeasurements formula unchanged: average electricity/max(1,20−outsideC), existing rounded percentage/COP/cycle/comfort outputs. A zero before or after normalized mean yields no percentage claim. Sensitivity is reviewed change−all-selected change in percentage points when both valid. No causal/energy-saving guarantee or revised certification score. Show original cohort counts, missing/duplicate/invalid/unusual flags and both denominators.
- Readiness: insufficient if a comparison is blocked/has<3 distinct days; review if coverage missing, heuristic flags remain, or absolute mean outdoor difference>3°C / indoor difference>1°C; ready otherwise. These flags are explicitly descriptive review rules, not a validated experiment certification.

Golden fixture: beforeOct1..4 electricity20/day at0°C; afterOct5..8 electricity10/10/10/90 at0°C. All selected normalized means1 and1.5 →−50%. Explicitly excluding afterOct8 with reason gives1 and0.5 →+50%; sensitivity+100percentage points. Raw90 remains unchanged; unusual Oct8 flagged rather than automatically excluded.

## Persistence and error boundary
Use a separate app_state key per experiment, quality_review_v1:<id>, no changes/deletions to measurement/experiment/profile/pro rows. Strict JSON decoder rejects malformed/trailing/future/wrong-experiment/unknown-shape content. Missing key is first use/default, not corruption recovery.

Pure qualityRepository functions accept the existing async SQL boundary and perform existing-row validation plus parameterized upsert on the transaction-scoped client inside withExclusiveTransactionAsync. Failed decode/write preserves old row and fails; UI publishes saved state only after successful commit. Loading/saving errors are visible with retry and draft retained; invalid existing review blocks replacing it. No automatic reset/repair. Per-experiment rows isolate separate review saves; Save is disabled while in flight.

Node tests use an actual temporary SQLite database via node:sqlite and a small test-only async port adapter, not mocked SQL outcomes. A real SQL trigger abort exercises rollback; selected raw readings, old experiment and pro_entitlement bytes remain unchanged. Native Expo SQLite adapter and full app remain root acceptance.

Expo transaction reference: https://docs.expo.dev/versions/latest/sdk/sqlite/#withexclusivetransactionasynctask — queries execute on txn, automatic commit/rollback; supported iOS/Android, not web. No new web parity claim.
